# 自动归档：信息架构规范

自动归档的每个阶段都在同一套目录规范和命名规范下工作。整理完成后，任何工作区都应满足：

- 一个类别只有一个归宿；
- 一个文件夹只装一类东西；
- 同一文件夹里的文件名遵循同一个模板。

规范以代码为唯一事实来源：`ArchiveConvention`（目录规范与类别词典）和 `ArchiveNamingRule`（命名规范）。审计、审阅、归组、分层四个阶段的提示词都在末尾附上同一段 `ArchiveConvention.ruleText`，不再各写各的规则；按类型归类等本地逻辑也读取同一个规范。`ArchiveNameNormalizer` 与 `ArchiveFolderNaming` 在本地强制执行规范，模型给出的名称只是建议。

安全边界不变：所有移动、改名、新建和删除空文件夹都经过 `ArchiveService` 的校验与预览（`previewAI` / `applyAI`），使用独占重命名，不覆盖同名文件，并写入可撤销的“整理记录”。

## 目录规范

| 规则 | 内容 |
| --- | --- |
| 顶层 | 顶层文件夹是“类别”或“项目”，同一层不混用两种维度。默认按类别组织；偏好为“按项目整理”时，项目内部可以有自己的类别子文件夹。 |
| 唯一归宿 | 每个类别在工作区内只有一个规范路径（canonical path）：工作区根目录下以规范名命名的文件夹。 |
| 命名 | 单层名称；不含 `/ : \`，不以 `.` 或 `~` 开头；不用无语义前缀（`A__`、`01_`）和占位名（`新建文件夹`、`temp`、`其他`、`杂项`、纯日期或纯数字）；同一父目录下不能有含义重复的名字（`照片` 与 `图片`）。 |
| 层级 | 通常一到三层，硬上限 4 层；同一层的分类维度一致。 |
| 语言 | 类别名语言与大小写风格在整个工作区一致，默认中文。 |

### 类别词典

| 规范名（中文 / 英文） | 部分同义名 | 依据 |
| --- | --- | --- |
| 音乐 / Music | Music、music、歌曲、Songs、音频、Audio | 音频扩展名 |
| 视频 / Videos | 影片、电影、Movies、Video | 视频扩展名 |
| 图片 / Images | 照片、截图、Photos、Pictures | 图片扩展名 |
| 文档 / Documents | 资料、文稿、Docs | 文档、表格、演示文稿扩展名 |
| 安装包与镜像 / Installers | 安装包、镜像、软件、Apps、ISO | 安装包与磁盘镜像扩展名 |
| 密钥与凭据 / Credentials | 密钥、凭据、密码、令牌、Keys、Secrets、Tokens | 证书与密钥扩展名，以及文件名中的 token、secret、password、id_rsa 等 |
| 代码 / Code | 源码、脚本、Source、Scripts | 源代码扩展名 |
| 压缩包 / Archives | 压缩文件、Zips | 压缩格式扩展名 |
| 大文件 / Large Files | — | 无类别且不小于 512 MB |
| 待分类 / Unsorted | 未分类、Inbox | 无法识别的散落文件 |

`证书`/`Certificates` 刻意不作为“密钥与凭据”的同义名：这类文件夹常放证书扫描件而非 TLS 证书。

用户偏好可覆盖词典中某个类别的名字（如“图片叫相册”），但覆盖后同一个类别仍只有一个名字。

## 命名规范

模板：`主题[_类型][_日期][_编号][_版本].原扩展名`

- 字段按证据取舍，顺序固定，字段之间用 `_`；字段内部的多个词用 `-`（或按偏好用空格，整个工作区一致）。
- 日期统一为 `YYYY-MM-DD`，只在原名已有日期时保留并规范写法（`20261019`、`2026.10.19`、`2026年10月19日` 都写成 `2026-10-19`），不凭修改时间编造。
- 必须保留：原扩展名及其大小写，原名中的日期、编号、版本标识（`ArchiveAINamePolicy.identifiers`）。
- 必须去除的噪声：`(1)`、`(2)`、` - 副本`、`copy`、`final`、`最终版2`、多余空白与连续分隔符、首尾标点、全角括号。合并时的同名冲突不再写成 `名称 (2).ext`，而是用模板的编号字段：`名称_2.ext`。

示例：

| 原名 | 规范名 |
| --- | --- |
| `report final (1).pdf` | `report.pdf` |
| `2026-10-19 发票.pdf` | `发票_2026-10-19.pdf` |
| `20261019 scan INV-0042 v2.1.pdf` | `scan_2026-10-19_INV-0042_v2.1.pdf` |
| `合同 - 副本.docx` | `合同.docx` |

### 文件夹的局部命名模式

每个文件夹有自己的命名模式，同一文件夹内所有文件用同一个模式。目前有两种：

- 模板（默认），附该文件夹常见的字段，如 `主题_日期_编号`；
- `歌手 - 歌名`（“音乐”类的默认模式）。

模式在第一次整理该文件夹时，从其中已有文件名的共同结构推导；推导不出时用该类别的默认模式或全局模板。结果写入 `archive.sqlite` 的 `folders` 集合（路径、类别、命名模式、最近审计时间、纯净度），之后的文件沿用，不再每批重新推导。工作区根目录里的散落文件按各自类别的默认模式命名。

### 本地强制执行

- `ArchiveNameNormalizer`：所有写盘前的文件名都先经过它——模型的建议、合并冲突、按类型归类、归组和规范化改名都不例外。模型的名称不符合模板时在本地纠正（恢复原扩展名、把丢失的日期和编号放回对应字段）；纠正不了才回退到规范化后的原名，并把模型的建议记入 `suggestedName`。
- `ArchiveFolderNaming`：文件夹名同样在本地规范化；模型返回类别的同义名时自动换成规范名，占位名和纯日期名不被采用。

## 阶段顺序

先定结构，再放文件。每个阶段结束前不进入下一阶段。

| 阶段 | 内容 |
| --- | --- |
| 0 结构审计 | 对整棵目录树逐个文件夹判断：对应词典中的哪个类别或哪个项目；名字是否符合规范，不符合给出规范名；是否纯净。纯净度由本地统计：直接文件中超过阈值（默认 30%，可配置）属于另一类别时标记为混合文件夹，并列出应拆出的文件。模型只判断语义等价和取名；所有文件夹都能由词典确定且名称合规时不请求模型。 |
| 1 规范化结构 | 同一类别的文件夹全部并入规范路径（无论在第几层、是否在项目夹内部；项目模式下项目内的类别夹保留并改用规范名）；重命名不合规的文件夹（含顶层，如去掉 `A__`）；把混合文件夹中不属于它的文件移到各自类别的规范路径；按上次自检结果纠正不符合所在文件夹模式的文件名。 |
| 2 审阅文件 | 小批量审阅新文件和变化的文件。`folder` 只能是已有文件夹（阶段 1 之后即类别的唯一归宿或项目夹），不能新建类别夹，类别同义名指向该类别的归宿；`name` 按目标文件夹的局部命名模式输出并经本地规范化。歌曲、视频、安装包和大文件按类型归类：判断依据只有一个——当前路径是否就是该类别的规范路径或其子目录，不是就移过去。 |
| 3 归组 | 散落文件放进新建或已有的文件夹。新文件夹名必须通过目录规范校验；与词典类别同义时直接使用规范名，文件进入该类别唯一的归宿。 |
| 4 分层 | 相关子文件夹归入新的上级文件夹。新名字和改名同样经过校验；根目录下的类别归宿不会被移动或改名。 |

阶段 0 的触发条件：目录结构签名变化，或上次审计失败，或上次自检有未解决的问题（连续三次仍未解决后不再强制审计，留给用户处理）。模型请求失败不会被当作“已完成”：审计记为失败，状态条提示原因，下次整理重试；此时仍执行词典能确定的本地决定。

## 一致性自检

整理结束后在本地检查（不请求模型）：

- 是否有两个以上文件夹映射到同一类别，或类别文件夹不在规范位置；
- 是否有不符合目录规范的文件夹名；
- 每个文件夹内的文件名是否符合该文件夹的命名模式。

结果保存在 `archive.sqlite`，显示在状态条（有问题时）和详情栏（未选中文件时），并作为下一轮阶段 0 的输入：未解决的项下一轮优先处理。

## 用户偏好

“整理规范”中仍可用自然语言填写偏好，但它被解析为对 `ArchiveConvention` 的覆盖项，而不是直接拼进提示词：类别名语言（中文 / 英文）、字段内的词分隔符（`-` / 空格）、按类别或按项目整理、混合文件夹阈值，以及某个类别的名字。其他内容一律忽略，偏好不能扩大任何权限。修改偏好后，下次整理会在新规范下重新审计整棵目录树。

# 自动归档：进度、本机模型与本地存储

## 完善后的开发提示词

请优化自动归档的分析体验与数据存储：

1. 分析过程中在状态卡片上持续展示进度：先显示“正在查看文件”，扫描完成后给出确定进度条（已处理/总数）、当前轮次与阶段（等待新文件稳定、等待模型回复、正在整理），并显示已用时间。模型回复期间显示已收到的字符数，避免长时间等待看起来像卡死。
2. 本机模型（Ollama 或 localhost/局域网地址）使用更宽松的连接参数：空闲超时 240 秒、单轮总时长 1200 秒；远端服务保持 90 秒/300 秒。空闲超时按“多久没有收到任何数据”计算，而不是整个回答的时限。
3. 请求改为流式（`stream: true`）：每个数据块都会重置空闲计时，模型边想边写不会因为首个字节慢或中间停顿被截断。兼容不支持流式的服务（一次性 JSON 响应）。
4. 对支持的本机推理服务关闭思考链：请求同时携带 `think: false`（Ollama）与 `chat_template_kwargs.enable_thinking = false`（llama.cpp、vLLM、LM Studio），未知参数会被忽略。输出仍会剥离 `<think>…</think>` 与代码围栏，只解析 JSON 对象。
5. 本机模型使用更小的批次（12 个文件、40 个关键词），远端保持 30 个文件、80 个关键词，提示词更短、回答更快、更不易被截断。首轮失败时自动以一半批次重试一次。
6. 区分“方案无效”和“服务不可用”：服务超时、HTTP 错误或流内错误时重试后向用户报告原因，不把这些文件标记为已处理；方案校验失败仍按原有逻辑放弃并记录。
7. 扫描阶段的关键词提取结果按文件指纹缓存，后续轮次对未变化的文件直接复用，减少重复解析 PDF/Word 的时间。扫描同时返回本轮未纳入的待处理文件数，用于进度总量。
8. 归档记录从单个 `archive.json` 改为本机 SQLite 数据库 `archive.sqlite`：配置、版本、学习报告保存在 `meta` 表，规则、建议、操作记录、观察、缓存、方案与已处理标记按行保存到 `records` 表。每次提交只写入发生变化的行，并在单个事务中提交。
9. 旧版 `archive.json` 首次打开时自动导入，并重命名为 `archive.json.migrated` 保留，不删除原始记录。仍保留目录独占锁，防止多个实例同时写入。
10. 增加针对流式解析、思考内容剥离、截断与错误处理、批次上限、关键词缓存以及存储往返与旧记录迁移的自动化测试。

## 使用方式

- 选择文件夹后，卡片会显示进度条、已处理数量、当前轮次和用时；点击“停止”可随时中止。
- 使用本机 Qwen 等模型时，可在模型设置中选择 Ollama 或填写本机 Base URL。若服务未启动或模型未加载，会提示具体的连接问题。
- 归档数据位于 `~/Library/Application Support/inchspace/AutoArchive/archive.sqlite`；同一目录下的 `archive.lock` 保证单实例写入。

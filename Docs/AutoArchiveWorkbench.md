# 自动归档：全宽工作台、纯 AI 整理与本机模型提速

## 完善后的开发提示词

请按下面的要求重做“自动归档”页面和整理流程：

### 一、页面布局（与应用其他页面一致）

1. 页面改为全宽布局，和“环境变量”“运行中心”等页面使用同一套头部（`AppFeatureTitle` + `appFeatureHeaderBackground`）、面板（`appSurface`）和按钮样式，不再是居中的窄卡片。
2. 删除右上角的“…”菜单，所有入口平铺在页面头部：`立即整理 / 停止`、`暂停 / 恢复`、`更换文件夹…`、`在访达中显示`、`重新整理全部`（需确认）、`模型设置`。
3. 页面分为三块：
   - **状态条**：当前状态（整齐 / 正在处理 / 出错 / 未配置模型）、所在文件夹、进度条、已处理数量、轮次、模型回复进度、已用时间，以及本次处理的统计（已完成、未归位、失败）。
   - **文件列表**（主区域）：逐个文件一行，列为“状态、文件、变更、主题、时间”。“变更”列必须直接写明做了什么：`改名 旧名 → 新名`、`移到 旧文件夹 → 新文件夹`、`保持不变`、`未归位`、`失败`。支持按“全部 / 已移动 / 已改名 / 未归位 / 失败”筛选和按名称搜索。列表同时包含本次运行的实时状态和此前所有处理记录，重新打开应用后仍能看到哪些文件被改过。
   - **侧边详情栏**：点击一行显示该文件的基本信息（当前位置、原名、创建时间、修改时间、大小）、AI 得出的主题与一句话摘要、本次变更（原名 → 新名、原文件夹 → 新文件夹）、判断依据、模型建议但未采用的名称；提供“撤销此文件”和“在访达中显示”。详情下方是“整理记录”，按批次列出并可撤销。
4. 首次引导保留三步（欢迎 → 选文件夹 → AI 说明），去掉“仅在本机整理”的选项；未配置模型时引导用户先去模型设置。

### 二、去掉本机整理

5. 删除 `ArchiveLocalPlanner` 及“改用本机整理 / 使用 AI 整理”的切换。整理一律由 AI 完成；未配置可用模型时不开始整理，在状态条中提示并提供“模型设置”入口。

### 三、单文件处理提速并记录文件信息

6. **成批询问、逐个执行**：扫描得到的文件按小批（本机模型 5 个、远端 10 个）放进同一次模型请求，模型对每个文件分别给出 `name`（新名或原名）、`folder`（已有文件夹或当前文件夹）、`fits`（是否属于所在文件夹）、`topic`（2–8 字主题）、`summary`（一句话说明文件内容/用途，≤40 字）、`reason`。拿到答案后仍然**逐个文件**用新的目录快照校验并执行，安全检查和记录方式不变。某一批答案无法解析时对半拆分重试，直到单个文件；单个文件两次无效则记为“未识别”，留在原处。
7. **提示词可被缓存**：系统提示词固定不变；用户消息先放稳定的内容（文件夹列表），再放本批文件，使本机推理服务（llama.cpp、LM Studio、Ollama）的前缀缓存能命中，减少重复预填充。模型返回用短编号引用文件，不回传 UUID。请求携带 `temperature: 0`，`max_tokens` 按批量大小计算，而不是固定 6000。
8. **减少磁盘读取**：移动文件前后的多次完整哈希改为“小文件（≤ 8 MB）完整哈希、大文件只比对设备/inode/大小/修改时间”；超过 64 MB 的文件在扫描时只对头尾各 4 MB 与大小做采样哈希。关键词提取缩短：PDF 最多 8 页、文本最多 6000 字符。执行文件操作后不再清空关键词缓存。
9. **写盘更省**：`ArchivePersistence.save` 只重新编码与上一次状态不相等的记录，其余记录直接复用已编码的数据。
10. **记录文件基本信息**：每条文件记录增加创建时间、一句话摘要、移动前所在文件夹和对应的操作 ID；修改时间和大小来自指纹。这些信息在列表和详情栏中展示，并用于“撤销此文件”。

### 四、针对本机 Qwen3.5 9B 的性能与发热

11. 本机模型的参数：每批 5 个文件、每个文件最多 24 个关键词、文件夹列表最多 120 项、同目录示例文件最多 10 个、合并与分层的候选列表相应缩短；两次模型请求之间停顿 0.5 秒，整理任务以 `utility` 优先级运行，让模型与磁盘的负载有起伏而不是持续满载。
12. 继续关闭思考链（`think: false` 与 `chat_template_kwargs.enable_thinking=false`），流式读取并以空闲超时计时；输出剥离 `<think>` 与代码围栏后只解析 JSON。
13. 不改变已有的安全边界：所有移动仍经过 `ArchiveService` 的校验、预览、独占重命名和可撤销的记录。

### 五、测试

14. 更新测试：批量审阅的编码/解码（含编号映射与拆分重试）、大文件采样哈希的稳定性、记录新增字段的持久化、`ArchiveLocalPlanner` 相关测试移除。

## 使用方式

- 页面头部的按钮即全部功能入口；“重新整理全部”会先弹出确认。
- 列表中的“变更”列直接写明每个文件的改动；点击一行，在右侧查看它的创建/修改时间、大小、主题、摘要和判断依据，可单独撤销。
- 使用本机 Qwen3.5 9B 时，在模型设置里选择 Ollama 或填写本机 Base URL；首批请求因为要加载模型会慢一些，之后同一文件夹的请求能复用前缀缓存。
- 旧的“本机整理”已移除；没有配置模型时整理不会开始。

## 已知限制

- 大于 64 MB 的文件只做采样哈希，头尾与大小都相同但中间内容被改写的文件会被视为未变化。
- 前缀缓存是否生效取决于推理服务（llama.cpp/LM Studio 默认开启；Ollama 对同一模型连续请求时复用）。

## 后续调整：公平调度、按类型归类与文件浏览器

- **为什么总在整理同一批音乐文件**：扫描结果按路径排序，每轮只取前 15/30 个；`A__MyTokens/Music/单曲` 排在最前且文件很多，其他文件夹一直排不到。运行被中断（停止、`URLError.cancelled` 被当成失败显示为 “cancelled”）时 `stampUnresolved` 不会执行，未归位文件下次又被优先取出。现在：新文件优先于复查文件，同一优先级内各文件夹轮流取文件；中断时也会给未归位文件打上当前结构标记；停止请求不再显示为失败。
- **按类型归类，不发给模型**：音频、视频、安装包/磁盘镜像，以及 ≥ 512 MB 的任何文件（`ArchiveFileKind`）不读内容、不请求模型。已在同类文件夹（名称匹配或同目录多数为同类）中的保持不变；其余放进已有的同类文件夹（前两层中名称匹配的，如 `Music`），没有就在工作区新建 `音乐 / 视频 / 安装包与镜像 / 大文件`。大文件只有在工作区根目录时才移动。移动仍走 `previewAI/applyAI`，可撤销。不支持提取正文的格式不再整文件读入内存。
- **文件浏览器**：主区域改为类似访达的浏览器（`ArchiveBrowserView.swift`）：路径栏、前进/后退、列表（名称/整理状态/主题/大小/种类/修改日期，可排序）与图标两种视图，双击进入文件夹或打开文件。每个文件图标右下角有状态角标（已整理、已移动、已改名、未归位、失败、处理中、等待），文件夹角标汇总其下所有文件的状态。筛选（本次/已移动/已改名/未归位/失败）或搜索时改为列出所有文件夹中的匹配结果。

## 后续调整：每个文件都要有结果，位置从整棵目录树里找

- **“未识别”的原因**：本机记录中 53 个“未识别”文件的原因全是“没有得到有效的结果”，而且在路径上是连续的整批。LM Studio 等服务运行 Qwen3.5 时可能忽略 `enable_thinking: false`，思考内容计入 `max_tokens`；原来按答案长度给的预算（单文件约 300 token）会被思考吃光，回答被截断，拆到单个文件后两次都失败，于是记为未识别。现在本机模型每次请求额外留出 3000 token 的思考余量，并在用户消息末尾加上 Qwen 的 `/no_think`；答案字段更短（summary ≤ 30 字、reason ≤ 20 字）。
- **更多识别依据**：每个文件除文件名、扩展名、关键词外，还带完整相对路径和系统元数据（`ArchiveFileMetadata`：种类、大小、创建/修改日期，以及 Spotlight 的标题、作者、专辑、页数、尺寸、时长、下载来源网站等）。模型额外返回 `known`（能否判断是什么）和 `confidence`；把握低于 0.4 的移动不执行。
- **在整棵树里找位置**：每轮读取一次所有文件夹的内容（`ArchiveFolderCatalog`：路径、文件数、扩展名分布、示例文件、已识别主题），本地按“文件夹名词语 ×3 + 内容词语 + 同类扩展名占比”为每个文件挑出最像的 6～8 个文件夹，连同其中的示例文件和主题一起发给模型对比，不再只依据当前所在文件夹和按字母截断的文件夹列表。
- **实在认不出的文件**：在子文件夹里的保留原处（记为已整理，不改名）；在根目录的，若本地找到明显相似的文件夹就放进去，否则统一放进工作区的「待分类」。「待分类」里的文件在文件夹结构变化后会再看一次。若一批多个文件全部拿不到结果，说明模型本身有问题，整理会停下并提示，不会把文件都扔进「待分类」。旧版本留下的“未识别”记录会重新识别一次。
- 同一次运行中已经处理过的文件不会因为文件夹结构变化而被再次送给模型；重新识别但没有移动的文件保留之前的来源与撤销信息。

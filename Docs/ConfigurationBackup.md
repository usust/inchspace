# 本地配置备份与恢复

## 入口与范围

在「设置 → 数据与备份」中使用「导出配置…」和「导入配置…」。应用不再自动读取或写入旧版 iCloud 同步文件；旧云文件和旧同步设置键不会被主动删除。

备份包含：

- 启动台的程序、目录、网站入口，项目名称、分组、排序和布局。
- 打开项目后隐藏窗口、窗口位置策略。

不包含应用本体、目录内容、密码、私钥、API Key、沙盒授权、当前选中页，以及服务器、运行中心、终端、自动归档、系统环境等其他模块的数据。Dock、菜单栏和全局快捷键也不受导入影响。

备份仍可能包含本地路径、项目名称、完整网址及自定义图标地址。这是普通 JSON 文件，没有应用层加密，分享前请检查内容。用户可以自行把文件保存到 iCloud Drive 或其他备份位置，这不代表应用提供自动同步。

## 导出和导入

导出使用系统保存面板，扩展名为 `.inchspacebackup`。快照取自当前内存中的已完成编辑，而不是可能滞后的磁盘内容；正在拖动的中间布局不被导出。

导入先读取、校验并展示预览。只有点击「备份当前配置并导入」后才开始替换：备份中没有的现有启动台项目会被移除，但实际应用和文件不会被删除。取消或校验失败不修改配置。

程序与目录入口不携带跨设备授权。仅当 ID 和目标都与本机项目匹配时恢复本机授权；其余入口提示检查或重新授权。预览不访问这些目标、不请求目录权限、不打开网站、不执行任务。导入后也不会自动打开入口。

## 恢复备份

每次确认导入后、修改当前配置前，先生成同格式恢复文件：

`Application Support/vip.lylab.inchspace/ConfigurationBackups/before-import-<UUID>.inchspacebackup`

Application Support 由系统返回；沙盒运行时可能在应用容器内。通过「在 Finder 中显示恢复备份」可以找到真实位置，无需手动推测路径。再次导入恢复文件即可恢复其覆盖的配置。文件不会自动清理，也不会覆盖之前的恢复备份。

恢复备份写入失败会停止导入。启动台采用原子文件写入，只有写入成功后才替换内存状态；偏好应用阶段发生错误时，协调器尝试恢复原启动台及偏好。进程内回滚保留原本的设备授权，不依赖已经剥除授权的便携备份文件。

启动台文件与 UserDefaults 不是跨存储原子事务，不能保证断电或进程强制终止时两者同时提交。恢复备份用于这种情况下的手动恢复。UserDefaults 也不提供逐次持久化失败的抛错接口，测试中的偏好失败通过依赖注入验证回滚路径，不等于能够检测所有操作系统持久化故障。

当前本机启动台无法解码时，会停止导出和导入，避免将临时空白布局当成有效原数据覆盖；此时需要先修复或恢复本机文件。

## 格式与限制

- UTType：`vip.lylab.inchspace.configuration-backup`，继承 `public.json`。
- 顶层 `format`：`inchspace.configuration-backup`。
- `schemaVersion`：1。
- `includedSections`：`library`、`preferences`。
- `payload.library`：严格解析的可移植启动台数据。
- `payload.preferences`：严格解析的两项通用偏好。
- `exportedAt`：ISO 8601；`appVersion`：导出应用版本。

使用专用严格 DTO，不复用旧启动台兼容解码的缺省行为。缺失必需字段、未知版本、重复标识或目标、不一致的分组关系、不合法的路径和网站协议均拒绝导入。网站仅允许 HTTP/HTTPS。旧版两个 iCloud 裸 JSON 不作为新版备份自动导入。

单文件上限为 10 MiB，最多 10,000 个入口和 5,000 个分组。这是小型配置文件而非文件归档，限制用于避免不可信输入消耗过多内存或阻塞界面。文件读取在后台使用有界读取，并验证普通文件，拒绝目录及 FIFO。

## 验证

- `ConfigurationBackupTests`：格式往返、严格字段、版本、目标、分组、大小、普通文件与设备数据剥离。
- `ConfigurationImportTests`：当前内存快照、预览不修改数据、恢复备份、写入失败、偏好部分失败回滚、回滚失败提示、防抖保存、授权匹配和损坏本机数据保护。
- `PortableDataTests`：便携副本与匹配本机授权恢复。
- `AppWindowPreferencesTests`：通用偏好持久化、设备设置保留、旧同步时间不再更新。
- `LaunchpadLayoutEngineTests`：原有启动台布局与持久化回归。

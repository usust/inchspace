# 寸空间 UI 优化提示词

请作为熟悉 SwiftUI、AppKit 与 macOS 原生交互的产品设计工程师，直接升级寸空间现有项目的 UI。产品面向在 Mac 上管理应用、目录、服务器、命令任务与文件的用户；用户偏爱卡片布局，希望页面层次更清楚、交互更流畅、AI 更自然地融入工作。

## 目标

围绕 macOS 27 的使用环境，采用当前 SDK 实际支持的原生材质、布局与交互 API。以 Apple 的 Liquid Glass 设计方向为参考：导航与操作浮于内容之上，内容本身保持清晰可读。不要将未经核实的设计主张或新 API 当作 macOS 27 的官方要求。保留项目现有最低系统版本与业务行为。

## 视觉体系

- 采用 SF 系统字体；命令、路径和代码使用系统等宽字体。页面标题约 24pt，卡片标题 13–16pt，正文 13pt，辅助信息 11–12pt。
- 配色以 macOS 语义色为准。设计参考：浅色画布 #F3F5F8、浅色内容 #FFFFFF、深色画布 #1C1D21、深色内容 #282A30、强调蓝 #3478F6、辅助灰 #6C727C。实际实现优先使用系统自适应颜色与现有 AccentColor。
- 页面左右留白约 24pt，分区间隔 20–24pt，内容卡圆角 18pt，嵌套区域 10–12pt，工具层 20–22pt。不要把每一行信息都包装成独立卡片。
- 用轻描边、合理留白与少量阴影表达层级；不堆叠背景光斑、不铺满玻璃、不用大幅装饰渐变。
- 内容左对齐。管理页在大窗口限制阅读宽度；终端与文件浏览器充分利用可用空间。

## 页面改造

1. 主导航保留原生列表选择、键盘访问及全部入口，增加清晰的产品标识与设置入口反馈。
2. 统一页面标题区、操作区和卡片底层组件，升级所有复用这些组件的页面。
3. 启动台将分类控件与项目工作区分层，保留拖拽、分页、分组和打开行为。
4. 设置采用分类导航与内容双栏；窄窗口使用紧凑分类选择器。切换分类不丢失原有设置逻辑。
5. 运行任务与服务器页面统一卡片层级，保留主操作、状态、配置与次要操作的优先顺序。运行状态必须同时具备文字或图标表达。
6. 文件浏览器将本地与远程目录视作并列工作区；保留表格选择、拖放、路径输入、传输队列与确认流程。
7. 自动归档按用途组织目录卡片，保留建议审阅和移动前确认。

## AI 体验

- 将 AI 设计为当前终端的协作面板。顶部说明协作对象与状态，正文采用回答卡与命令卡，底部固定上下文开关和输入区。
- 空状态给出具体且可解释的入口，例如解释错误、检查环境、生成命令。点击建议先填入输入框，让用户能补充意图后发送。
- 上下文开关明确显示是否共享终端内容；连接信息、附加选区、模型信息保持可读。
- 命令卡清晰区分复制、插入、请求运行、等待授权、运行中、退出状态；保留已有高风险命令校验与授权策略。
- 流式生成保持稳定布局；用户滚动阅读历史时，不反复强制拉到末尾。提供回到最新消息的入口。
- 错误提示提供设置和重试入口，输入框具有明确的发送、停止与键盘操作反馈。

## 动画与可访问性

- 动画用于操作反馈：卡片悬停、按钮按压、分类选择、侧栏开合、状态变化、附件移除与复制成功。动画约 0.16–0.28 秒，使用克制的 ease-out 或低弹性 spring。
- 不给实时指标或每个流式字符施加布局动画；不添加持续闪烁、循环漂浮或每次加载依次弹出所有卡片的效果。
- 尊重 Reduce Motion、Reduce Transparency 和 Increase Contrast；减少动态效果时禁用位移、缩放与弹性。
- 保留可见键盘焦点；仅图标按钮具备可访问名称；状态信息不能仅依赖色彩。

## 实施要求

直接修改项目源码，先理解现有架构并复用共享组件。保护工作区已有修改，不重置文件，不引入无关业务功能或新增依赖。完成后使用可用的 Xcode SDK 构建验证，检查明暗模式、窗口缩放、键盘和 AI 状态布局。无法在环境中完成的验证应明确说明；不要将静态检查等同于实际运行验证。交付可审阅的代码与变更说明。
